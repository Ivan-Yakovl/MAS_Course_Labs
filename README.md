Четыре лабораторные работы на базе одной складской многоагентной системы:
от спецификации и архитектуры до сравнения координации, переговоров за ресурс

и не требует API-ключей. Правила агентов, назначений, переговоров и защиты
реализованы явно, без готовой агентной платформы.

## Прикладная задача и архитектура

На склад поступают заказы с координатой, специализацией, трудоёмкостью,
сроком и приоритетом. Автономные рабочие агенты различаются скоростью,
специализацией и положением. Каждый робот выполняет один заказ, затем
обращается к общей погрузочной станции ёмкости один.

В системе выделены четыре роли:

- **D — диспетчер:** хранит очередь и выбирает исполнителей.
- **Wi — рабочие агенты:** оценивают задания, принимают работу и запрашивают ресурс.
- **S — станция и арбитр:** выдаёт непересекающиеся слоты обслуживания.
- **M — монитор:** проверяет завершения и полномочия, контролирует аренду и восстановление.

В ЛР 2 сравниваются циклическая диспетчеризация и контрактная сеть с
CFP / PROPOSE / ACCEPT / REJECT. В ЛР 3 исследуется насыщенная конкуренция
за станцию: исходная политика по ID сравнивается с предложениями слота,
приоритетами, старением и арбитражем. В ЛР 4 изолирован контрольный контур:
проверки владельца и версии, подтверждение физического выполнения,
идемпотентность, аренда, карантин и повторные вызовы средства.

## Экспериментальное исследование

Используются **30 фиксированных seed от 0 до 29** и одинаковые входы внутри
каждой сравниваемой пары режимов.

| Исследование | План | Запусков |
| --- | --- | ---: |
| ЛР 2 | 5 конфигураций × 30 seed × 2 механизма | 300 |
| ЛР 3 | 2 профиля приоритетов × 30 seed × 2 политики | 120 |
| ЛР 4 | 8 сценариев, включая контроль × 30 seed × 2 режима защиты | 480 |
| **Всего** | | **900** |

Ключевые наблюдения при заданных условиях:

- **ЛР 2:** без задержки связи устойчивого выигрыша контрактной сети по времени
  не установлено. При задержке 1 такт в конфигурации с 6 роботами средний
  момент завершения — **517,8 такта** у диспетчера и **561,3** у контрактной сети.
  Число сообщений — **720** и **1320** соответственно.
- **ЛР 3:** при равных приоритетах индекс Джейна вырос с **0,1667 до 0,9990**,
  а число агентов без обслуживания уменьшилось с **5 до 0**. Цена — рост
  числа сообщений примерно в **6,9 раза**.
- **ЛР 4:** во всех **210 защищённых запусках с воздействием** выполнены все
  12 заказов с согласованным учётом. Проверено семь типов воздействий:
  ложное завершение, подмена цели, отказ станции, чужое назначение,
  цикл передачи, устаревшая отмена и повтор сообщения DONE.

Доверительные интервалы, полные таблицы, объяснение эффектов и границы
интерпретации приведены в отчётах. Эти выводы относятся к выбранной модели
и нагрузке; они не являются гарантией безопасности при неизвестных атаках.

## Быстрый запуск

### 1 Скачать исходники

```console
git clone https://github.com/Ivan-Yakovl/MAS_Course_Labs.git
cd MAS_Course_Labs/labs/lab01/project
```

Можно вместо Git скачать ZIP и открыть терминал в папке `project` любой работы.
Для точного повторения сохранённых результатов рекомендуется **Python 3.12**;
расчёты выполнены на Python 3.12.14. Внешние библиотеки устанавливать не нужно.
На Windows при необходимости замените `python` на `py -3`.

### 2 Выбрать исследование

Команды выполняются из папки `project`:

```console
# ЛР 1 — базовая демонстрация контрактной сети
python mas.py --lab 1 --mechanism contract --out demo_trace.json

# ЛР 2 — сравнение механизмов на одинаковом seed
python mas.py --lab 2 --mechanism central --seed 0 --out central.json
python mas.py --lab 2 --mechanism contract --seed 0 --out contract.json

# ЛР 3 — до и после арбитража
python mas.py --lab 3 --policy greedy --out greedy.json
python mas.py --lab 3 --policy negotiated --out negotiated.json

# ЛР 4 — ложное завершение без защиты и с защитой
python mas.py --lab 4 --scenario false_done --out baseline.json
python mas.py --lab 4 --scenario false_done --protected --out protected.json
```

Список аргументов: `python mas.py --help`.
Для ЛР 4 доступны `clean`, `false_done`, `goal_hijack`, `tool_outage`,
`forged_assignment`, `delegation_cycle`, `stale_cancel`, `replay_done`.

### 3 Воспроизвести всё исследование

```console
python -m unittest -v test_mas.py
python experiments.py
python build_demo.py
python audit_results.py
```

`experiments.py` пересоздаёт 900 запусков и результаты в `results/`.
`build_demo.py` собирает автономный HTML из новых трасс.
`audit_results.py` заново выполняет все сохранённые запуски, сверяет каждое
поле, независимо проверяет интервалы станции и пересчитывает статистику из CSV.
Эти команды перезаписывают результаты в выбранной копии проекта.

## Данные и проверка качества

В `results/lab2_raw.csv`, `lab3_raw.csv`, `lab4_raw.csv` находятся все отдельные
запуски. `summary.json` хранит средние и половины 95% доверительных интервалов.
`manifest.json` фиксирует среду, seed и SHA-256 расчётных исходников.

Сохранённый [независимый аудит](labs/lab01/project/results/quality_audit.json)
подтвердил **900 повторных запусков**, **12 300 значений показателей**,
**199 статистических сводок** и непересечение слотов во всех **900 трассах**.
Все **10 поведенческих тестов** прошли, включая проверку некорректных сообщений,
просроченной аренды и независимости защиты от названия сценария.

Для проверки комплектности репозитория из его корня:

```console
python scripts/verify_repository.py
```

PDF-отчёты отрендерены и просмотрены постранично. Скрипты HTML-демонстрации
проверены программно для всех 20 режимов; визуальная проверка в браузере
в среде подготовки была недоступна.

## Ограничения модели

- Это дискретная имитация в одном процессе. Такты не равны миллисекундам,
  обмен сообщениями не использует настоящую сеть.
- В ЛР 2 сетевые фазы сведены к задержке начала работы. В ЛР 3 и ЛР 4 обмен
  атомарен в пределах такта; их абсолютное время не сравнивается с ЛР 2.
- Координата склада одномерная; столкновения и реальные траектории не моделируются.
- В ЛР 4 доверены D, S, M и физический журнал среды. Криптография,
  компрометация центра и комбинации нескольких воздействий не исследовались.
- Демонстрация воспроизводит сохранённые трассы. Новые расчёты запускаются через Python.
