# Складская многоагентная система

Учебный проект для четырёх лабораторных по теории МАС. Вся ключевая логика
распределения задач, переговоров и защиты реализована явно в `mas.py`.
Сторонние библиотеки для работы системы не нужны. Python 3.10 или новее.

Выполнил: Яковлев Иван, группа Б24-517, МИФИ.

## Быстрый просмотр

Откройте `demo.html` двойным щелчком. Интернет и сервер не требуются.
Выберите режим, нажмите «Следующее сообщение», «Воспроизвести» или «К итогу».
Это просмотр сохранённых реальных трасс seed=0, а не выполнение новых расчётов.

## Запуск модели

Команды выполняются из каталога проекта:

```console
python mas.py --lab 1 --mechanism contract --out lab1.json
python mas.py --lab 2 --mechanism central --seed 0 --out central.json
python mas.py --lab 2 --mechanism contract --seed 0 --out contract.json
python mas.py --lab 3 --policy greedy --out greedy.json
python mas.py --lab 3 --policy negotiated --out negotiated.json
python mas.py --lab 4 --scenario false_done --out baseline.json
python mas.py --lab 4 --scenario false_done --protected --out protected.json
python mas.py --help
```

Сценарии ЛР 4: `clean`, `false_done`, `goal_hijack`, `tool_outage`,
`forged_assignment`, `delegation_cycle`, `stale_cancel`, `replay_done`.
Ключ `--protected` включает защиту. Все трассы содержат итог и сообщения.

## Повторение исследования

```console
python -m unittest -v test_mas.py
python experiments.py
python build_demo.py
python audit_results.py
```

`experiments.py` выполняет 900 запусков: ЛР 2 — 300, ЛР 3 — 120,
ЛР 4 — 480. Используются seed=0..29. Повторное выполнение перезапишет
`results/` и после `build_demo.py` — демонстрацию.
Расчёт воспроизводим в Python 3.12; проверенная среда указана в manifest.json.
Другие версии Python могут менять генерацию случайных входов, поэтому для
точного воспроизведения предпочтительна Python 3.12.

## Состав

- `mas.py` — агенты, сообщения, распределение, арбитраж, инъекции отказов.
- `experiments.py` — серии запусков, доверительные интервалы, сырые данные.
- `test_mas.py` — проверки поведения и инвариантов.
- `audit_results.py` — независимое повторение 900 запусков, проверка трасс и статистики.
- `results/lab2_raw.csv`, `lab3_raw.csv`, `lab4_raw.csv` — все отдельные запуски.
- `results/summary.json` — средние и половины 95% интервалов.
- `results/manifest.json` — параметры среды и SHA-256 расчётных исходников.
- `results/quality_audit.json` — результат независимой проверки сохранённых данных.
- `results/traces/` — 20 полных демонстрационных трасс.
- `demo.html` — автономный просмотр трасс.
- `build_demo.py`, `demo_template.html` — исходники демонстрации.

В CSV `messages` — число логических сообщений, `ticks`/`makespan` —
модельные такты, а не миллисекунды. Обмен не использует реальную сеть.
Строка trace имеет `seq`, `tick`, `src`, `dst`, `kind`, `task` и поля нагрузки.
Сообщения CFP/ACK могут записываться заранее с будущим tick; для просмотра
используется сортировка по (tick, seq). В ЛР 2 сетевые фазы сведены к задержке
старта задачи. Достоверность внешних сообщений в ЛР 4 проверяется в модели
доверенного канала; криптография и компрометация диспетчера не моделируются.
В ЛР 4 монитор продлевает аренду при подтверждённом ожидании ресурса и проверяет,
что она покрывает весь выдаваемый слот. Правила восстановления используют
наблюдаемое состояние, а не название сценария. `detection_delay` считается от
фактического начала воздействия; `recovery_delay` — до корректного завершения
затронутого заказа, а для отказа средства — до первого завершения после его восстановления.

ЛР 3 и ЛР 4 — изолированные конфигурации ролей этой МАС. Они используют
отдельные циклы симуляции для исследования ресурса и контрольного контура;
результаты этих конфигураций не следует сравнивать по времени с ЛР 2.

## Соответствие отчётам

ЛР 1: спецификация, роли, граф и протоколы; базовая демонстрация `--lab 1`.
ЛР 2: `Warehouse`, 5 конфигураций × 30 seeds × 2 механизма.
ЛР 3: `ResourceTrial`, 2 профиля приоритетов × 30 seeds × 2 политики.
ЛР 4: `ReliabilityTrial`, 8 сценариев × 30 seeds × 2 режима защиты.

Отчёт не содержит листингов и демонстрационных кадров. Они вынесены в это
приложение. Опубликованный репозиторий курса:
https://github.com/Ivan-Yakovl/MAS_Course_Labs

В репозитории каждая лабораторная находится в отдельной папке `labs/lab01` …
`labs/lab04` с отчётом, своей инструкцией и полной копией `project`.
Общее ядро МАС одинаково во всех четырёх комплектах: копии позволяют передавать
папку одной лабораторной отдельно и выполнять её без соседних каталогов.
